# 世界内容方案

本文记录"程序生成世界 + 手工摆放内容"的整体方案：已经实现的部分、设计决定和理由，以及后续计划。具体的编辑操作见 [关卡编辑指南.md](关卡编辑指南.md)。

---

## 1. 要解决的问题

世界由噪声函数在运行时生成，在 IDE 里打开场景是空的。要在某个具体位置放刷怪点、城区或特效，只能凭坐标猜测，再运行游戏验证，效率很低。

## 2. 候选方案

| 方案 | 做法 | 优点 | 缺点 | 状态 |
|---|---|---|---|---|
| **A. IDE 内预览** | 用 `@runInEditor` 组件在场景视图里画出地形，内容用组件摆放 | 和普通 Laya 场景编辑一样；数据存在场景文件里；不用另写编辑器 | 只能预览有限范围 | **已实现** |
| B. 游戏内编辑模式 | 运行时按键进入编辑模式，点击放置，导出 JSON | 所见即所得，能看到怪物实际行为 | 要自己写编辑 UI 和导入导出 | 保留 |
| C. 世界俯视图 | 把大范围地图导出成 PNG，每格一个像素 | 适合规划大布局 | 不适合精细摆放 | 保留 |

选择 A 作为主要的工作流程。B 和 C 以后按需补充。C 可以直接复用小地图的贴图生成代码。

## 3. 关键设计

### 3.1 确定性是前提

世界的每一部分都由种子和坐标算出，没有任何运行时随机：

- 地形、水、道路、树、石头：`generateChunk(cx, cz)`，纯函数。
- 刷怪点里每只怪物的出生位置：`spawnPosition(info, i, nav)`，由刷怪点坐标和序号算出。

所以编辑器里算出的结果和游戏里完全一致。编辑器预览不需要和游戏共享任何运行时状态，只要调用同样的函数。

仍然使用 `Math.random()` 的地方只有怪物的闲逛路线和思考间隔，以及 G 键的目的地。这些只影响行为，不影响地图和出生位置。

### 3.2 数据和组件分离

```
SpawnPoint（编辑器组件，存在场景文件里）
    │ toInfo()
    ▼
SpawnInfo（纯数据）──► SpawnRegistry（按块索引）──► MonsterManager（块加载时生成）
                    └► Minimap（画范围圈）
```

- 组件只负责编辑：暴露属性、画编辑器标记。
- 运行时逻辑只认 `SpawnInfo`。以后方案 B 导出的 JSON 也能转成 `SpawnInfo`，直接加进同一个 `SpawnRegistry`，其余代码不用改。

### 3.3 按块生成和回收

- 刷怪点按**中心所在的块**建索引，块加载时生成怪物。
- 每只怪物记住自己的**出生块**（`originKey`），出生块卸载时回收。

以前的做法是按怪物**当前所在的块**回收。追击中跑到别的块的怪物不会随出生块回收，出生块重新加载时又会再生成一份，导致重复。现在的做法修复了这个问题。

### 3.4 编辑器节点不污染场景

预览地形和刷怪点标记都设置了 `HideFlags.HideAndDontSave`，不会出现在层级面板里，也不会存进场景文件。游戏运行时（`LayaEnv.isPlaying === true`），这两个组件的编辑器逻辑直接跳过。

### 3.5 小地图

- 每个块生成一张 32×32 的贴图，1 格 = 1 像素，颜色复用地形的 `COLORS` 表。
- 贴图缓存起来，地图层只在玩家移动约 1 像素时重画。图标层每帧重画。
- 格子被修改（砍树）时，`invalidate(cx, cz)` 只丢掉那一块的缓存。
- 每帧最多新生成 12 块贴图，打开大地图时分几帧画完。
- 缓存超过 1200 块时，回收显示范围外的贴图。
- 因为地图数据是确定性的，小地图不依赖块是否已经加载画面，没去过的地方也能画。

## 5. 已知限制

- **未实测**：代码通过了 TypeScript 类型检查，但还没在 IDE 和浏览器里实际运行验证。
- **怪物不能被杀死**：现在还没有战斗系统，怪物只会闲逛和追击。
- **刷怪点不会复活**：怪物在块卸载时回收，重新加载时全部重新生成。有了战斗系统后，需要记录击杀状态和复活时间。
- **砍树记录不持久**：修改只保存在内存中，刷新页面就丢失。
- **预览范围有限**：编辑器里一次最多预览 17×17 块。
- **修改 SEED 会破坏已有布局**：刷怪点存的是世界坐标，不会随地形变化。

## 6. 后续计划

按依赖顺序排列。前三步做完，就有第一个可玩的循环：接任务、找到刷怪点、杀怪、领奖励。

1. **战斗系统**：给单位加 HP 和攻击；玩家能攻击怪物，怪物贴身时攻击玩家；死亡后移除。
2. **事件总线**：`GameEvents` 统一派发 `monsterKilled`、`enterRegion`、`chopTree` 等事件。任务、特效、小地图都只监听事件。
3. **任务系统**：配置表定义任务（目标类型 `kill` / `reach` / `collect` / `talk`）；`QuestManager` 监听事件推进进度；HUD 显示任务栏。刷怪点的节点名作为任务目标的引用。
4. **刷怪点复活**：在 `SpawnPoint` 上加复活时间属性，记录每只怪物的击杀时间。
5. **特效**：`FxManager` 加对象池，分三层：跟随怪物的、刷怪点区域常驻的、事件触发的。粒子在 IDE 里做成预制体。
6. **更多内容组件**：照 SpawnPoint 的模式做 `TownArea`（城区，在 `generateChunk` 里把格子改成地板和墙）、`TriggerZone`（触发区）、`FxPoint`（场景特效点）。
7. **存档**：砍树记录、任务进度、击杀状态写入 `localStorage`。
8. **方案 B / C**：游戏内编辑模式；世界俯视图导出。
