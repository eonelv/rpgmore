### 1.3 核心设计原则

- **确定性**：相同种子 + 相同坐标 = 相同结果。使用 `hash2` 代替 `Math.random`。
- **纯函数**：`generateChunk`、`terrainHeight`、`spawnPosition` 等都是纯函数。
- **数据与画面分离**：`NavGrid`（寻路数据）和 `ChunkManager`（渲染网格）独立工作。
- **流式加载**：按玩家位置动态加载/卸载块，每帧时间预算内构建。

## 3. 噪声系统

文件：`src/world/Noise.ts`

### 3.1 hash2 — 确定性哈希

```
hash2(x, z, seed) → [0, 1)
```

三次整数乘法 + 异或混合，把任意整数坐标映射到 [0,1)。所有需要"随机"数的地方都用它，保证确定性。

### 3.2 valueNoise — 值噪声

```
valueNoise(x, z, seed) → [0, 1)
```

在整数格点上用 `hash2` 取值，中间用 hermite 插值（`t²(3-2t)`）平滑过渡。

### 3.3 fbm — 分形布朗运动

```
fbm(x, z, octaves, seed) → [0, 1)
```

多层值噪声叠加，每层频率×2、振幅×0.5。用于地形噪声、森林分布、山区分布等。

| 使用场景 | 频率缩放 | 层数 | seed 偏移 |
|---|---|---|---|
| 基础地形 | `wx/140, wz/140` | 4 | `SEED` |
| 山区分布 | `wx/240, wz/240` | 3 | `SEED+900` |
| 森林分布 | `wx/70, wz/70` | 3 | `SEED+500` |

### 3.4 ridgedFbm — 山脊噪声

```
ridgedFbm(x, z, octaves, seed) → [0, 1]
```

每层取 `1 - |2v-1|` 再平方，形成尖锐的山脊线。用于山体的脊线形态。频率缩放 `wx/110, wz/110`，5 层，seed 偏移 `SEED+700`。

低处细节减弱（weight 衰减），山谷更平滑、山脊更突出。

## 4. 世界生成

文件：`src/world/WorldGen.ts`

### 4.1 地形高度

```typescript
terrainNoise(wx, wz)    → [0, 1)   // 基础噪声
terrainHeight(wx, wz)   → 米       // 最终高度
groundY(wx, wz)         → 米       // 站立高度 = max(地形高度, WALK_MIN_Y)
```

| 参数 | 值 | 说明 |
|---|---|---|
| `WATER_Y` | `-2.0` 米 | 水面高度 |
| `WALK_MIN_Y` | `-1.85` 米 | 桥面/道路最低高度 = WATER_Y + 0.15 |

地形高度公式：
```
terrainHeight = (terrainNoise - 0.5) × 14 + mountainHeight
```

基础地形范围约 -7 ~ +7 米。低于水面的部分被水覆盖。

### 4.2 水体判定

| 参数 | 值 | 说明 |
|---|---|---|
| `WATER_NOISE` | `0.36` | terrainNoise < 此值则为水 |

沙滩阈值：`0.395`（terrainNoise 在 0.36~0.395 之间为沙地）。

### 4.3 山体生成

| 参数 | 值 | 说明 |
|---|---|---|
| `MOUNTAIN_HEIGHT` | `42` 米 | 山峰最大高度 |
| `MOUNTAIN_CELL_MIN` | `2.2` 米 | 山体高度超此值的格子为不可走的 Mountain |
| `ROAD_KEEP` | `0.04` | 道路中心保留的山体比例（山口有轻微隆起） |

山体高度公式：
```
mountainHeight = mask × (0.1 + ridge² × 1.1) × MOUNTAIN_HEIGHT × roadValley
```

- `mask`：山区分布遮罩（低频 fbm，smoothstep 0.52~0.64）× 排水遮罩（smoothstep 0.40~0.50）
- `ridge`：山脊噪声的平方（尖锐的脊线）
- `roadValley`：道路切开山体的山谷系数

### 4.4 格子生成规则

`generateChunk(cx, cz)` 的生成流程：

1. **遍历每个格子**，按世界坐标计算类型：
   - `mountainHeight > 2.2` → Mountain（最先判断）
   - `terrainNoise < 0.36` → Water
   - `terrainNoise < 0.395` → Sand
   - `terrainNoise > 0.66` → Rock
   - 否则按森林噪声和随机数决定 Grass / Tree / Rock
2. **叠加道路**：检查附近所有道路（主干道、小路），在道路半宽范围内的格子改为 Road 或 Bridge（水上）
3. **填充封闭区域**：块内完全被围住（不接触边缘、没有道路/桥）且小于 40 格的空地 → Bush

### 4.5 森林与零散物件

| 条件 | 结果 |
|---|---|
| `fbm(森林) > 0.56 && hash2 < 0.45` | 密林中的树 |
| `hash2 < 0.025` | 零散的石头 |
| `hash2 < 0.06` | 零散的树 |

### 4.6 封闭区域检测

| 参数 | 值 | 说明 |
|---|---|---|
| `POCKET_MAX` | `40` | 小于此格子数的封闭区域被填成灌木 |

使用 BFS 洪水填充：从每个未访问的可走格子开始扩散，如果整个连通区域不接触块边缘且没有道路/桥，且面积 < 40 格，全部改为 Bush。

## 5. 道路网生成

文件：`src/world/WorldGen.ts`

### 5.1 大区系统

| 参数 | 值 | 说明 |
|---|---|---|
| `REGION_CHUNKS` | `8` | 大区边长（块数） |
| `REGION` | `512` 米 | 大区边长 = 8 × 64 |

世界按 512 米的正方形大区划分，每个大区有一个枢纽点（`regionHub`）。

### 5.2 枢纽点

枢纽点在大区中心附近，有 ±0.2 个大区（约 ±102 米）的抖动。选点逻辑：
- 依次尝试 8 个候选位置
- 取第一个在陆地上的（terrainNoise > 0.42）
- 大区 (0,0) 的第一个候选是出生点附近的固定位置 `(34, 52)`

### 5.3 主干道

| 参数 | 值 |
|---|---|
| `HIGHWAY.half` | `6.4` 米（路面半宽，路宽约 13 米） |
| `HIGHWAY.valleyIn` | `9` 米（山谷完全压低的范围） |
| `HIGHWAY.valleyOut` | `18` 米（山谷恢复原高的范围） |
| `HIGHWAY.maxBridge` | `30` 米（能修桥的最长水面） |

相邻大区（上下左右）的枢纽之间修一条弯曲的主干道：
- 折线由 32 段组成（`POLY_SEGS = 32`）
- 横向偏移 = `sin(πt) × (bias + 噪声摆动)`，bias 是绕行量，摆动幅度 35 米（`valueNoise(t×4, seed, SEED+61)`），两端正好落在枢纽上
- 遇到长于 30 米的水面，依次尝试 7 种绕行量（0, ±70, ±140, ±200 米）
- 都绕不开就不修这段路

### 5.4 小路

| 参数 | 值 |
|---|---|
| `TRAIL.half` | `2.2` 米（路面半宽，路宽约 4 米） |
| `TRAIL.valleyIn` | `4` 米 |
| `TRAIL.valleyOut` | `10` 米 |
| `TRAIL.maxBridge` | `6` 米（只跨很窄的溪流） |

每个大区 0~2 条小路（`hash2 * 3` 取整）：
- 从该大区的 +x 或 +z 方向主干道中段分叉
- 方向大致垂直于主干道，随机偏转 ±0.4 弧度
- 长度 90~220 米
- 遇到宽于 6 米的水面就在岸边结束（截断到水面前 3 米）

### 5.5 道路查找

`roadsNearChunk(cx, cz)` 查找可能影响块的道路：
- 外扩 `ROAD_MARGIN = 20` 米
- 搜索周围 5×5 个大区拥有的所有道路
- 结果按块缓存，主干道排在前面（判定优先）

### 5.6 山谷效果

`roadValley(wx, wz)` 返回 [ROAD_KEEP, 1]：
- 每条道路有自己的 `valleyIn` 和 `valleyOut`
- 在 `valleyIn` 范围内山体压到 `ROAD_KEEP = 0.04`（几乎平地）
- 在 `valleyIn` 到 `valleyOut` 之间用 smoothstep 过渡
- 多条道路取最小值

### 5.7 山路

高山上修一条盘山小路，从山顶通到山脚（山体高度 < `MOUNTAIN_CELL_MIN` 的可走地面），坡度不超过 `MTN_GRADE`。

| 参数 | 值 | 说明 |
|------|-----|------|
| `PEAK_MIN` | `14` 米 | 山体高度超过此值的山峰修山路 |
| `PEAKS_PER_REGION` / `PEAK_SPACING` | `2` / `200` 米 | 每个大区最多 2 座，彼此至少相距 200 米 |
| `MTN_GRADE` | `0.3`（约 17°） | 路面坡度上限 |
| `MTN_GRID` / `MTN_GRID_R` | `8` 米 / `22` 格 | 规划网格，山路最远伸出约 176 米 |
| `MTN_HALF` | `1.8` 米 | 路面半宽（Road 格子） |
| `MTN_FLAT` / `MTN_FALL` | `3.5` / `10` 米 | 地面完全压到路面 / 恢复原高的距离 |
| `MTN_MAX_CUT` | `5` 米 | 路面与原始地形差超过此值就停止往上修 |

生成步骤（`regionMountainTrails`，按大区缓存）：
1. 大区内每 16 米采样山体高度，取最高的候选点，爬坡到局部最高处作为山峰
2. 以山峰为中心在粗网格上做 Dijkstra（16 方向，含马步），超过坡度上限的边代价 ×80，路自然沿等高线绕成之字形；水面不能走。
   终点必须落在已有道路上（`isTrailGoal`）：只走到山体边缘不够，山脚常是散石区、密林或被群山围住的盆地，会走不出去。附近没有道路的山峰不修山路
3. Chaikin 平滑两次，按 3 米重采样；路面高度取原始地形，平滑后从山脚往上夹坡度
4. 挖方/填方超过 `MTN_MAX_CUT`，或之字形两段挨得太近（< `MTN_GAP`）时截断

地形：`terrainHeight` = `rawHeight` 向山路路面高度插值，系数为 `1 - smoothstep(MTN_FLAT, MTN_FALL, d)`；附近多段路面按 `1/(d⁴+0.05)` 加权。块生成时距中心线 ≤ `MTN_HALF` 的格子（水除外）设为 Road。
`mountainSegsNearChunk` 按块缓存附近 3×3 大区的山路线段。

### 5.8 出生点

```typescript
spawnPoint() → { gx, gz }  // 全局格子坐标
```

出生点 = 大区 (0,0) 的枢纽点，主干道交汇处。当前种子下约为世界坐标 `(-99, 75)`。

## 6. 块管理与流式加载

文件：`src/world/ChunkManager.ts`

### 6.1 加载策略

- 玩家跨块时重新计算需要加载的块
- 按距离从近到远排入构建队列
- 每帧在时间预算内构建（默认 `budgetMs = 4` ms）
- 离开卸载半径的块立即销毁

### 6.2 开局预热

`warmUp(px, pz)` 立即构建玩家周围 3×3 块，避免开局掉进空白区域。

### 6.3 块重建

`rebuild(cx, cz)` 用于格子修改（砍树）后立即重建该块的地形网格。水面网格保留不变。

### 6.4 每个块的内容

| 组件 | 说明 |
|---|---|
| `root` | Sprite3D 容器节点 |
| `terrain[]` | 地形网格数组（按材质层分组） |
| `water` | 水面网格（可能为 null） |
| `meshes[]` | 地形 Mesh 引用，销毁时释放 |

### 6.5 回调

```typescript
onChunkLoaded(cx, cz)    // 块加载后，用于生成怪物
onChunkUnloaded(cx, cz)  // 块卸载后，用于回收怪物
```

## 7. 寻路数据层

文件：`src/world/NavGrid.ts`

### 7.1 数据管理

- 每块数据 = 32×32 字节的类型数组
- 按需生成（纯函数、确定性）
- 未加载画面的块也能参与寻路
- 离玩家太远（`NAV_KEEP_RADIUS = 8` 块）的数据被回收

### 7.2 玩家修改

`edits: Map<chunkKey, Map<格子索引, 新类型>>`

- 砍树等修改永久保存在内存中
- 块数据被回收后重新生成时会叠加修改
- 修改触发 `version++` 和 `onCellChanged` 回调

### 7.3 格子查询

```typescript
kind(gx, gz)           // 全局格子坐标 → 格子类型

nearestWalkable(gx, gz, radius)  // 最近的可走格子
lineClear(ax, az, bx, bz, radius)  // 直线无阻挡检测（用于路径平滑）
```

## 8. 寻路算法

文件：`src/world/PathFinder.ts`

### 8.1 算法概述

分层 + 分帧的格子 A*：

| 层 | 说明 |
|---|---|
| 低层 | 8 方向 A*，禁止斜穿墙角 |
| 高层 | 目标超过 `MAX_SPAN = 3` 块时分段规划 |
| 分帧 | 每次 `step(400)` 展开最多 400 个节点 |

### 8.2 搜索范围

| 参数 | 值 | 说明 |
|---|---|---|
| `MAX_SPAN` | `3` | 高层分段距离（块） |
| `MARGIN` | `2` | 搜索范围外扩（块），给绕湖/绕山留空间 |

搜索范围 = 起点块与终点块围成的矩形 + MARGIN 块边距。

### 8.3 不可达处理

世界不保证处处连通（大湖、山脉会挡路）。当 A* 开放列表为空（到不了目标）时：
- 返回到**已探索节点中离目标最近的**位置的路径
- `PathResult.reached = false`
- 单位会走到湖边/山脚停下

### 8.4 路径平滑

从起点出发，跳到最远的一个能直线到达的点（`lineClear` 检测），消除锯齿形路径。

### 8.5 PathService

```typescript
constructor(nav, budgetMs = 3)  // 每帧 3ms 预算
request(from, to, onDone)       // 提交请求
update()                        // 每帧调用，推进队列
```

多个单位同时寻路时排队处理，避免卡帧。

### 8.6 PathResult

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` | boolean | 是否找到了路 |
| `points` | Vec2[] | 世界坐标路径点（已平滑），不含起点 |
| `partial` | boolean | 是否只是远处目标的一段 |
| `reached` | boolean | 是否到达了目标（false = 到不了，走到最近处） |
| `expanded` | number | 展开的节点数 |

## 9. 网格构建器

文件：`src/world/MeshBuilder.ts`

### 9.1 顶点格式

```
POSITION(3) + NORMAL(3) + COLOR(4)         // 10 floats，无贴图
POSITION(3) + NORMAL(3) + COLOR(4) + UV(2) // 12 floats，有贴图
```

每个三角形三个顶点各自独立的法线（平面着色），低多边形风格。

### 9.2 索引限制

| 参数 | 值 | 说明 |
|---|---|---|
| `MAX_VERTS` | `65000` | 单个 Mesh 的最大顶点数（16 位索引） |

接近上限时自动切分出新的 Mesh。

### 9.3 法线方向

法线通过参考点 `(rx, ry, rz)` 确定方向：法线朝远离参考点的方向。地面的参考点在下方 `(x, -1000, z)`，法线朝上。

### 9.4 绕序

Laya 的正面是"法线方向看过去为顺时针"。如果法线点积表明方向反了，会交换 B 和 C 顶点修正绕序。

### 9.5 UV 自动投影

当 `uvTile > 0` 且没有传入 UV 时，根据法线主方向选择投影面：
- `|ny|` 最大 → 投影到 xz 平面
- `|nx|` 最大 → 投影到 zy 平面
- `|nz|` 最大 → 投影到 xy 平面

坐标减去 `uvOriginX/Z`（块的原点），避免远处 UV 过大损失精度。

### 9.6 几何体生成

| 方法 | 说明 | 用途 |
|---|---|---|
| `tri` | 单个三角形 | 基础 |
| `quad` | 四边形（两个三角形） | 地面、桥面 |
| `box` | 轴对齐盒子 | 树干、栏杆、桥墩 |
| `boulder` | 不规则石块（两圈顶点 + 顶点，6 面） | 山上的大石块 |
| `rock` | 圆润可拉伸的石头（三圈顶点 + 顶点，7 面） | 散落石头、灌木叶簇 |
| `cone` | 圆锥（不画底面） | 树冠 |

## 10. 地形渲染

### 10.1 材质层

地形网格按材质分成 8 层，各用一个 `BlinnPhongMaterial`：

| 层 | 着色方式 | 贴图 | 用途 |
|---|---|---|---|
| `base` | 纯顶点色 | 无 | 物件（树/石头/灌木/桥栏杆/桥墩）、水底 |
| `grass` | 贴图 × 顶点色，alpha 测试 | 草地 | 草地、山上长草的区域 |
| `sand` | 贴图 × 顶点色，alpha 测试 | 沙地 | 沙滩 |
| `plank` | 贴图 × 顶点色 | 木板 | 桥面 |
| `rock` | 贴图 × 顶点色 | 岩石 | 山体 |
| `gravel` | 贴图 × 顶点色 | 砂石 | 道路 |
| `trail` | 贴图 × 顶点色，alpha 测试 | 砂石（alpha 里是参差边缘） | 山路：顶点 alpha 按到山路中心线的距离计算，画成连续的砂石带，盖在草地层上面（抬高 0.42）。山路格子本身按原来的地面（山体/草地）画，路上和路边不放石块、松树 |
| `granite` | 贴图 × 顶点色，法线投影 UV | 花岗岩 | 散落石头（圆润型）及其地面 |
| `strata` | 贴图 × 顶点色，法线投影 UV | 层状砂岩 | 散落石头（石板/石柱型）及其地面 |

### 10.2 贴图归一化

所有贴图平均亮度归一化到 `TEX_MEAN = 0.85`，顶点色乘以 `TEX_GAIN = 1/0.85 ≈ 1.176` 补偿。

这样整体颜色仍由 `COLORS` 表决定，和小地图保持一致，贴图只负责细节变化。

### 10.3 Alpha 测试过渡

草地和沙地材质使用 `MaterialRenderMode.RENDERMODE_CUTOUT`，`alphaTestValue = 0.5`。

顶点 alpha = `0.5 + 0.5 × 周围4格的权重平均`：
- 草地格子权重 1，山体格子权重 = `mountainGrass(h, slope)`
- 贴图 alpha 经过直方图均衡映射到 [0.55, 0.85]（缩小后过渡带更窄，减少孤立碎块）
- 像素保留条件：`顶点alpha × 贴图alpha ≥ 0.5`
- 边缘处形成参差的自然过渡，而不是直线裁切
- 全水格顶点按深度延伸沙地（0.2m 以内全覆盖，1.6m 以下消失），遮盖水底深褐色

### 10.4 相邻块一致性

`buildChunkMeshes` 接收 `kindGlobal` 回调，能读取相邻块边缘的格子类型。确保：
- 地面过渡（草地 alpha）在块边界连续
- 桥栏杆在块之间连续
- UV 使用块内坐标，块之间无缝（贴图 tile 是 CHUNK_SIZE 的因数）

### 10.6 山体着色

- **草地权重** `mountainGrass(h, slope)`：低处缓坡长草，高处陡坡露岩石
  - 公式：`1 - smoothstep(0.35, 0.8, (h-4)/7 + slope×0.75)`
- **岩石颜色** `mountainRockColor(h, slope, jitter)`：越高越浅，雪线附近犬牙交错
  - 雪线 `SNOW_LINE = 24` 米
  - 积雪公式：`(h - 24 + jitter×4) / 3 - slope×0.8`，陡坡上积不住雪
- **山上的装饰**：
  - 雪线以下、草地权重 > 0.45、坡度 < 1.3 → 松树
  - 草地权重 < 0.5 → 大石块

## 12. 水面系统

### 12.1 水面网格

文件：`src/world/ChunkRenderer.ts` → `buildWaterMesh`

| 参数 | 值 | 说明 |
|---|---|---|
| `WATER_Y` | `-2.0` 米 | 水面高度 |

### 12.2 水面 Shader

文件：`assets/resources/RpgWater.shader`

#### Uniform 参数

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `u_ShallowColor` | Color | `(0.25, 0.65, 0.72, 0.45)` | 浅水颜色和透明度 |
| `u_DeepColor` | Color | `(0.06, 0.26, 0.50, 0.88)` | 深水颜色和透明度 |
| `u_SkyColor` | Color | `(0.72, 0.85, 0.95, 1.0)` | 天空反射色 |
| `u_SunDir` | Vector3 | `(-0.4, 0.8, 0.45)` | 太阳方向 |

#### 顶点着色器

- 从顶点色 r 恢复水深（引擎会对顶点色做 gamma 校正，需要 `pow(r, 1/2.2)` 还原）
- 两组正弦波产生轻微起伏，岸边（depth=0）不动避免穿插

#### 片元着色器

| 效果 | 实现 |
|---|---|
| 基础水色 | `mix(shallow, deep, smoothstep(0, 0.6, depth))` |
| 水下焦散 | 双层扭曲噪声，深水区可见（`causticMask = smoothstep(0.15, 0.5, depth) × 0.12`） |
| 菲涅尔反射 | `pow(1-NdotV, 3.5)`，最大反射量限制在 0.45 + 0.03 |
| 太阳高光 | Blinn-Phong，`pow(NdotH, 220) × 1.2` |
| 岸边泡沫 | 两层噪声叠加，带宽随时间脉动，碎片状裁切 |
| 透明度 | 按深度插值浅水/深水 alpha，泡沫区和高光区增加不透明度 |

#### 法线计算

4 组方向波梯度叠加（不同方向、频率、速度、振幅），浅水区减弱：

| 方向 | 频率 | 速度 | 振幅 |
|---|---|---|---|
| `(1.0, 0.3)` | 0.50 | 1.4 | 0.08 |
| `(-0.4, 1.0)` | 0.75 | 1.7 | 0.06 |
| `(0.7, -0.8)` | 1.50 | 2.4 | 0.030 |
| `(-1.0, -0.2)` | 2.60 | 3.0 | 0.015 |

### 14.1 数据结构

### 14.2 出生位置计算

```typescript

```

- 用刷怪点坐标的 hash 和序号 i 确定角度和距离

## 18. 近期调整记录

### 18.1 道路系统重构

**旧方案**：每个块有一个道路节点，相邻块之间修直线路。山体用道路距离函数切开山谷。全连通保证。

**新方案**：世界按 512 米大区划分，枢纽点 + 弯曲主干道 + 分叉小路。道路是弯曲折线，能绕行大水面。不再保证全连通。

| 变更 | 旧 | 新 |
|---|---|---|
| 道路形态 | 每块一个节点、直线相连、路宽约 2 格 | 大区枢纽 + 弯曲主干道（13m）+ 小路（4m） |
| 连通性 | 全连通（洪水填充保证） | 不保证（大湖、山脉可能隔断） |
| 封闭区域 | 所有不连通的可走格子 → 灌木 | 只有块内小于 40 格的封闭区域 → 灌木 |
| 山谷 | 固定 3~12 米宽，检查周围 3×3 块 | 每条道路有自己的宽度，按道路类型分别设置 |
| 山区分布遮罩 | `smoothstep(0.42, 0.58, …)` | `smoothstep(0.52, 0.64, …)`，山区更少、更集中 |
| 出生点 | `roadNode(0, 0)`，约 (33, 51) | `spawnPoint()`（大区 (0,0) 枢纽），约 (-99, 75) |
| `roadNode` 函数 | 导出 | 已移除 |

### 18.2 寻路适配

| 变更 | 旧 | 新 |
|---|---|---|
| 中间目标 | 目标块的 `roadNode` | 目标块中心附近最近可走格子 |
| 搜索范围 | 矩形 + 1 块 | 矩形 + `MARGIN = 2` 块 |
| 目标不可达时 | 直接返回 `ok=false` | 返回到最近可达位置，`reached=false` |
| `PathResult` | 无 `reached` 字段 | 新增 `reached` 字段 |

### 18.3 渲染系统升级

**旧方案**：单一材质层（纯顶点色），所有地面共用一个 BlinnPhongMaterial。

**新方案**：8 个材质层，程序化贴图，alpha 测试过渡。

| 变更 | 旧 | 新 |
|---|---|---|
| 材质层数 | 1（base） | 8（base/grass/sand/plank/rock/gravel/granite/strata） |
| 贴图 | 无 | 7 张程序化贴图，运行时生成 |
| 草地/沙地边缘 | 直线切割 | alpha 测试 + 直方图均衡噪声，参差自然过渡 |
| 山体着色 | `mountainColor` 单色 | 岩石层 + 草地层叠加，alpha 裁切过渡 |
| 石头物件 | 两个叠放的方块 | 5 种造型（`rock()` 多面体）+ 花岗岩/砂岩两种贴图 |
| 灌木物件 | 简单方块 | 4 种造型（圆团/开花/结果/高草） |
| 桥 | 一块平板方块 | 木板贴图桥面 + 侧边 + 临水栏杆 + 桥墩 |
| `buildChunkMeshes` 签名 | `(data) → Mesh[]` | `(data, kindGlobal) → ChunkMesh[]` |
| MeshBuilder | 只有 tri/quad/box/cone，无 UV | 新增 UV、顶点 alpha、自动法线投影 UV、`boulder()`、`rock()` |
| 山上装饰 | 无 | 草地上的松树、裸岩上的大石块 |

### 18.4 水面 Shader 改进

| 变更 | 旧 | 新 |
|---|---|---|
| 浅水颜色 | `(0.28, 0.72, 0.78, 0.55)` | `(0.25, 0.65, 0.72, 0.45)` |
| 深水颜色 | `(0.07, 0.30, 0.55, 0.92)` | `(0.06, 0.26, 0.50, 0.88)` |
| 天空反射色 | `(0.70, 0.84, 0.96)` | `(0.72, 0.85, 0.95)` |
| 焦散效果 | 无 | 双层扭曲噪声焦散暗纹 |
| 泡沫 | 单层噪声 | 双层噪声叠加 + 碎片状裁切 + 泡沫颜色带水色 |
| 菲涅尔 | `pow(4.0)` × 0.8 | `pow(3.5)` × 0.45，更通透 |
| 高光 | `pow(180) × 1.6` | `pow(220) × 1.2`，稍微收敛 |
| 深度映射 | `smoothstep(0, 1)` | `smoothstep(0, 0.6)`，更平滑 |
| 顶点起伏 | 无 | 两组正弦波，岸边不动 |

### 18.5 砍树邻块重建

旧方案：砍树只重建当前块。

新方案：因为地面过渡会读相邻块边缘的格子（草地 alpha），块边上的格子变化时邻块也要重建。Main.ts 的 `onCellChanged` 增加了 4 个方向的邻块重建检测。

### 18.6 编辑器预览适配

旧方案：`buildChunkMeshes(data)` 返回 `Mesh[]`，编辑器用单一材质。

新方案：`buildChunkMeshes(data, kindGlobal)` 返回 `ChunkMesh[]`，编辑器按 layer 分配对应材质。需要传入 `kindGlobal` 回调以支持相邻块过渡。
